# 보스 관리 상세 설계 — 7-A 확정 정책 반영

7-D 최신 사용자 정책: 수동 가격 입력·수정·해제 및 설정 적용은 제공하지 않는다. 이는 아래 7-A/7-C의 수동 입력 허용 정책을 대체한다. 신규 기록은 내장 가격/적용 시점으로 계산하거나 미산정으로 남긴다. 기존 수동 가격 스냅샷과 revision, SQLite v4 설정 행은 보존하되 설정은 신규 계산에 읽지 않는다. registration_flag를 완료 여부와 별개로 관측한다. 실응답과 사용자 제공 보스 이름의 일치는 확인했지만 인게임 난이도·초기화 경계 검증이 남았다. API 자동 관리 목록 구성은 보류하고 기존 수동 선택을 유지한다. [7-D 보고](STAGE_7D_REPORT.md)를 확인한다. 이하 수동 가격 기능 설명은 과거 설계/구현 이력이다.

갱신일: 2026-10-28. **D1~D12와 계산 정책은 사용자 확정 사항이다. 이 문서의 아래 내용은 7-A 설계 기준이며, 7-B에서 카드 진입·수동 UI·기록/계산/마이그레이션을 구현했다.** 7-C에서는 이번 사용자 요청에 따라 보스·난이도별 영구 수동 가격과 API 관측·사용자 수락을 구현했다. 현재 스키마는 v4이며 상세 구현·검증은 [7-C 보고](STAGE_7C_REPORT.md)를 따른다.

7-C 가격 정책 보완: 기존 기록별 가격 입력을 유지하면서 보스·난이도별 공통 설정을 추가했다. 해당 설정은 현재 주차 신규 기록에 사용하고 과거 주차에는 자동 소급하지 않는다. 기록 편집에서 난이도·날짜가 같고 새 가격을 입력하지 않으면 당시 가격을 유지한다. 설정을 해제하면 적용 시점이 확인되는 내장 가격으로 복귀하고, 확인할 수 없으면 미산정으로 남긴다. 아래의 “다른 주차/캐릭터로 자동 전파하지 않는다”는 기록별 입력 정책이며, 사용자가 별도로 저장하는 공통 설정과 구분한다. API 관측은 오늘 기준으로만 조회·수락하고 기존 기록과 충돌하면 기록 편집으로 안내한다. 아래 v2/미구현 표현과 소단계 분할표는 7-A 당시 설계 이력이다.

## 1. 기준과 현재 구현

[AGENTS](../AGENTS.md), [아키텍처](ARCHITECTURE.md), [개발 계획](DEVELOPMENT_PLAN.md), [6단계 보고](STAGE_6_REPORT.md), [API 레퍼런스](NEXON_MAPLESTORY_API_REFERENCE.md), 현재 Rust 저장소·도메인·API 클라이언트와 React 화면을 확인했다. 외부 maplemate 스킬은 사용하거나 참고하지 않았다.

## 2. 확정 운영 정책

Maple Ledger는 획득한 결정석을 모두 판매한다고 가정해 클리어를 메소 수익으로 환산한다. **판매 여부·판매일을 기록하지 않으며 클리어 귀속 기간에 수익을 즉시 반영한다.** 이는 앱의 계산 정책이며 실제 게임 잔액 조회나 실제 판매 증명을 의미하지 않는다.

| ID | 확정 사항 |
| --- | --- |
| D1 | 수동 클리어 기본, API 완료 관측은 사용자 확인 후 반영 |
| D2 | 주간 보스부터 지원 |
| D3 | 조사한 최신 가격을 내장하고 확인 불가 시 수동 입력 허용 |

기존 판매 확인·미판매 상태·판매 시각·판매 원장/이벤트·판매 취소/반대 거래 및 예상/판매 확정액 분리 설계는 폐기했다. 범용 회계 시스템을 이 단계에 도입하지 않는다. OCID 식별, 원자적 저장, 충돌 검사, 누락 시 보존, 가격 스냅샷, 기간별 이력 원칙은 유지한다.

## 3. 가격 조사와 내장 자료

보스별 가격·출처·적용일·불일치 상세는 [결정석 가격 및 규칙 조사](BOSS_CRYSTAL_RESEARCH.md)에 기록했다. 조사일은 2026-10-28이며 한국 정식 서버만 대상으로 한다. 테스트월드·해외 서버 가격은 현재 가격으로 채택하지 않는다.

- 2026-09-17 조정과 2026-10-22 추가 조정·신규 난이도를 함께 검토했다. 9월 가격표만으로 최신판을 만들면 안 된다.
- 공식 근거 항목과 보조 자료 대조 후보를 구분한다. 보조 자료의 일치만으로 공식 확인 표시를 하지 않는다.
- 누락/적용일 불명/출처 충돌은 null 및 상태로 표현하며 0으로 대체하지 않는다.
- 사용자 입력은 **1인 기준 결정석 전체 가격**이다. 분배된 개인 금액을 다시 나누는 실수를 막도록 단위를 표시한다.
- 수동 가격은 해당 기록의 보스/난이도·주차·근거·입력 시각을 보존한다. 다른 주차/캐릭터로 자동 전파하지 않는다.
- 공식 가격을 확인하지 못한 후보는 참고값으로 제시할 수 있으나, 사용자가 확인하여 수동 가격으로 적용하기 전에는 미산정으로 둔다.

내장 자료는 구현 단계에서 소규모 버전 JSON으로 제공한다. 이번에는 실제 데이터 파일/로더를 만들지 않는다.

| 범위 | 필드 후보 |
| --- | --- |
| 자료 묶음 | schema_version, dataset_version, region=KMS, checked_at, sources |
| 보스 항목 | boss_id, variant_id, 표시명, 난이도, cycle, clear_group_id, reward_type |
| 가격 이력 | price_id, variant_id, world_scope, solo_price_meso(십진 문자열/null), effective_from, effective_until |
| 근거·정밀도 | verification_status, source_ids, effective_time_precision, notes |
| 계산 규칙 | calculation_version=party_floor_v1, party_min, 검증된 party_max, rule_source_ids |

자료 묶음 버전과 개별 가격 유효일은 별개다. 변경되지 않은 가격은 기존 price_id를 유지한다. 유효 구간 중복을 검사한다. 점검 후 적용이라는 근거밖에 없으면 임의로 00시/04시를 넣지 않고 maintenance 정밀도로 둔다. 경계가 모호하면 사용자 확인을 받는다.

과거 주차에 오늘 가격을 소급 적용하지 않는다. 한 주차 중 가격이 바뀌면 필요한 경우 클리어/획득 날짜 또는 적용 버전을 확인받는다. 시점 불명은 미산정으로 기록할 수 있다. 새 가격표는 과거 스냅샷을 덮어쓰지 않는다.

## 4. 파티 수익 계산

확정 공식은 `개인 메소 수익 = 결정석 1인 기준 가격 / 파티 인원`의 **정수 몫**이다. 소수점 이하는 버린다.

- 솔로 1명, 입력 기본값도 1명이다. 실제 파티 조건은 사용자가 확인한다.
- 파티 인원은 필수 양의 정수다. 0·음수·소수·비숫자·정수 범위 초과를 거부한다. 보스별 공식 최대 인원이 확인되면 그 범위도 검사한다. 모든 보스에 동일한 6인 상한을 임의 적용하지 않는다.
- 가격은 메소 단위 양의 정수다. 0·음수·소수·범위 초과를 거부한다. 가격 미확인은 입력 오류와 별도로 미산정이다.
- Rust에서 최종 검증·계산한다. React 미리보기도 같은 정수 의미를 사용한다. Rust/SQLite i64 범위와 합계 오버플로를 검사한다. DTO 금액은 JS 안전 정수를 넘을 수 있어 십진 문자열을 사용한다.
- 인원 편집 시 미리보기를 다시 계산하고 저장 시 새 revision에 가격·인원·개인액을 함께 기록한다. 대상 주차와 변경액을 표시한다.
- 계획의 기본 인원 변경은 기존 클리어 기록을 바꾸지 않는다. 과거 정정은 해당 기록을 명시적으로 편집한다.
- 예: 4,040,000 / 3 = 1,346,666메소. 각 건의 정수 개인액을 합산하며 전체 가격을 합친 뒤 한 번 나누지 않는다.

공식 일반 가이드는 입장한 파티원 수가 가격에 영향을 준다고 설명한다. 관리 캐릭터 수나 생존자 수를 분모로 사용하지 않는다. 소수점 버림은 확정된 앱 정책이며 게임 내 반올림을 공식 문장으로 확인한 것은 아니다. 파티 이탈·보상 자격·특수 모드 예외는 조사 문서의 검증 상태를 따른다.

## 5. 클리어 저장·해제·수정·집계

한 주차/캐릭터/클리어 제한 그룹에 유효 기록은 하나다. 처치 횟수를 공유하는 난이도는 별도 수익으로 중복 기록하지 않는다. 난이도 변경은 같은 기록의 새 revision이다. 제한은 검증된 clear_group_id로 표현한다.

| 동작 | 유효 상태 | 현재 합계 |
| --- | --- | --- |
| 클리어 저장, 가격·인원 확인 | 완료 + calculated | 개인액 즉시 포함 |
| 클리어 저장, 가격 미확인 | 완료 + unpriced | 금액 제외, 미산정 건수 표시 |
| 인원/가격/난이도 정정 | 새 revision 완료 | 이전액 대신 새 금액 |
| 클리어 해제 | 새 revision 미완료 | 해당 수익 제외, 이력 보존 |
| 다시 완료 | 같은 기록의 새 revision | 최신액 한 번만 포함 |
| 반복 API 수락/중복 저장 | 동일 상태면 변경 없음 | 추가 수익 생성 없음 |

집계는 current_revision을 따라가 완료 AND calculated인 행만 더한다. 기록일·수정일로 수익 주차를 이동하지 않는다. 미산정은 `합계 X메소 · 미산정 N건`으로 표시한다. 수동 해제한 기록을 다음 API 조회로 자동 완료 처리하지 않는다.

기본 전체 합계는 현재 관리 OCID 집합과 대상 주차 기록을 조인한다. 선택 해제는 기본 합계에서만 제외되며 이력은 남는다. 과거 전체/개별 캐릭터 조회에서는 관리 해제 캐릭터도 찾을 수 있게 한다. 재선택해도 기록을 복제하지 않는다.

향후 8단계 메소 잔액 연결은 clear_id+current_revision의 유효 수익을 한 번만 참조하는 방향을 검토한다. 지금 별도 수입 이벤트·범용 원장·중복 금액 저장을 추가하지 않는다. 잔액 반영 및 과거 정정 연계 정책은 8단계에서 설계한다.

## 6. 주간 초기화와 게임 제한

주간 경계는 **목요일 00:00 KST(UTC+09:00)**다. 구간은 `[목요일 00:00, 다음 목요일 00:00)`이며 week_start_kst를 주차 키로 사용한다. ISO 주 번호/월요일 시작으로 계산하지 않는다. 근거와 예외는 [조사 문서](BOSS_CRYSTAL_RESEARCH.md)의 공식 가이드 링크를 따른다.

- 같은 보스 난이도는 공식 처치 제한 그룹을 공유한다. 여러 난이도를 각각 완료 처리해 중복 합산하지 않는다.
- 공식 공통 가이드의 캐릭터당 주간 보스 최대 12개 처치와, 삭제된 결정 판매 12개 제한은 다른 규칙이다. 판매 기능은 만들지 않는다.
- 로컬 완료 수와 API의 전체 완료 수를 더하면 중복이므로 합산하지 않는다. API 횟수는 참고 표시다. 최신 제한/범위가 불명확하면 경고하고 검증 없이 전역 강제 제한을 추가하지 않는다.
- 월드 판매 한도 등 실제 환금 제약은 남아 있다. 앱은 사용자 확정대로 전량 판매 가정으로 계산하며 한도로 수익을 자동 차감하거나 판매 상태를 만들지 않는다. 관리 밖 캐릭터까지 포함한 실제 판매 가능 총액을 보장하지 않는다.
- 월간 검은 마법사는 주간 목록·합계에서 제외한다. 일간으로 바뀐 보스·삭제된 난이도·결정석 미지급 시즌 콘텐츠도 제외한다.

새 주차에는 새 상태를 조회하고 이전 기록은 유지한다. 시작·절전 복귀·실행 중 경계에서 주차를 재계산한다. 종료 중 실행되는 서버/서비스는 없다. PC 시간 역행이나 늦은 API 응답으로 과거 기록을 재귀속하지 않는다. 기존 기간의 경계는 규칙 업데이트로 바꾸지 않는다.

## 7. 단순화한 SQLite 논리 모델

**제안이며 DDL·마이그레이션은 작성하지 않았다.** 판매/일반 금전 원장 테이블은 없다. 카탈로그·가격은 버전 JSON을 사용하고 필요한 이력 스냅샷만 SQLite에 저장한다.

| 테이블 후보 | 주요 필드·제약 | 역할 |
| --- | --- | --- |
| record_characters | character_id PK, ocid UNIQUE, account_id, world_name, 표시 정보 | 선택 교체와 독립된 영구 식별 |
| character_boss_plans | character_id+boss_id UNIQUE, variant_id, enabled, sort_order, default_party_size | 캐릭터별 보스·난이도·기본 인원 |
| boss_periods | period_id PK, cycle, start_at, end_at, timezone, reset_rule_version, UNIQUE(cycle,start_at) | 주차 경계 보존 |
| boss_clear_records | clear_id PK, character_id FK, period_id FK, clear_group_id, current_revision; UNIQUE(character_id,period_id,clear_group_id) | 중복 클리어/난이도 수익 방지 |
| boss_clear_revisions | PK(clear_id,revision), completed, boss_id/variant_id, 명칭/난이도·계정/월드 스냅샷, solo_price_meso nullable, party_size, personal_income_meso nullable, calculation_status, price_id/dataset_version/source/verification, calculation_version, clear_date nullable, recorded_at, source, reason, request_id UNIQUE | 계산 근거와 정정·해제 이력 |
| boss_observations (API 단계에만) | observation_id, character_id, query_date, observed_at, API 이름/난이도/주기, 매핑 결과, 등록/완료 상태 | 최소 관측, 원문 전체 저장 금지 |

가격 테이블 전체를 DB로 복제하지 않는다. 당시 표시명·가격·버전·출처·공식 스냅샷으로 카탈로그 항목이 없어져도 이력을 읽는다. clear_group_id 변경 시 기존 기록을 자동 병합하지 않고 기간별 규칙을 확인한다.

완료 기록에는 유효한 인원이 필수다. calculated이면 가격>0과 개인액의 정수 몫 일치를 Rust에서 검사한다. unpriced이면 개인액은 null이다. 미완료는 합산 대상이 아니며 해제 전 계산 근거는 이전 revision에 남는다.

### 저장 원자성과 이전

- 기존 revision 확인 → 새 revision 삽입 → current_revision 갱신을 한 트랜잭션으로 처리한다. expected_revision으로 동시 수정 손실을 막는다.
- 동일 request_id 재요청은 기존 결과를 반환한다. API 수락도 동일 클리어 기록 갱신이다.
- FK는 record_characters를 향하며 mutable managed_character/position을 참조하지 않는다. 이력 연쇄 삭제를 금지한다. FK 활성화와 무결성 검사를 구현 시 보장한다.
- v2를 보존하는 추가 마이그레이션을 사용한다. 현재 선택 OCID를 중복 없이 영구 식별에 등록한다. API 전체 목록 재조회와 개발 키 읽기는 불필요하다.
- 임시 DB로 실패 롤백, 백업/복구, 기존 본캐·순서·revision 보존을 검증한다. 실제 DB 변경은 7-B 승인 후 수행한다.
- HTTP 중 DB 쓰기 트랜잭션을 열어 두지 않는다. 적용 전에 캐릭터·기간·revision을 다시 검사한다.

## 8. 스케줄러 보조 조회 설계 유지

레퍼런스의 GET `/maplestory/v1/scheduler/character-state`를 사용한다. x-nxopen-api-key 헤더, 필수 ocid, 선택 date(조회 기준일, 생략 시 오늘)를 따른다. 자신의 계정 캐릭터만 조회 가능하다. 최대 14일 전까지 조회 가능하며 보스는 콘텐츠 완료 시 갱신된다. 해당 기준일에 미접속이면 응답이 없을 수 있다.

boss_contents의 content_name, difficulty, cycle, list_order_no, registration_flag, complete_flag를 사용한다. flag는 명세상 문자열이다. 누락·null·미지 값은 미확인으로 둔다. list_order_no는 보스 ID가 아니며 date/observed_at은 정확한 클리어 시각이 아니다. weekly_boss_clear_count/limit_count는 처치 수이며 가격·판매 정보가 아니다.

수동 흐름: `React → Command → Rust 규칙/서비스 → repository → SQLite`.

API 흐름: `사용자 조회 → 관리 OCID 확인 → OS 키 → 기존 NexonClient → 관측/매핑 → 사용자 확인 → 동일 클리어 저장`.

키는 React/SQLite에 전달하지 않는다. 실패·월드 불일치·미분류·귀속 기간 불명확은 적용을 보류한다. 계정은 기존 OCID 관계를 유지하며 이름으로 재식별하지 않는다. 같은 완료를 반복 수락해도 수익은 하나다. API false/누락으로 수동 기록을 바꾸지 않는다.

기존 reqwest·타임아웃·본문 상한·리다이렉트 차단·안전한 오류를 재사용한다. 렌더링으로 호출하지 않고 OCID/기준일 요청을 병합한다. 429는 배치를 중단하고 대기를 안내한다. 실제 API 구현/검증은 후속 단계다.

## 9. UI와 사용자 입력 예외

카드의 보스 관리 버튼에서 주차 화면으로 진입한다. 추적 보스·난이도, 필수 인원(기본 1), 클리어 체크, 적용 가격/출처, 개인 수익, 주간 합계를 표시한다. 대시보드는 현재 관리 캐릭터의 해당 주차 합계·미산정 건수를 표시한다.

- 가격/난이도/인원 편집 시 변경 후 금액을 보여주고 저장한다. 다른 난이도로 바꿀 때 같은 클리어 기록의 정정임을 알린다.
- 보조 자료만 있거나 가격이 없으면 1인 기준 가격 확인/직접 입력이 필요하다. 과거 가격 경계가 모호하면 날짜 또는 적용 버전을 확인받는다.
- 새 주차는 미확인 상태로 표시한다. 과거 조회는 기록을 바꾸지 않고 정정은 명시적으로 수행한다.
- API 관측에는 반영/기존 유지 동작을 제공한다. 판매 버튼·미판매 상태·판매일·예상/판매 확정 구분은 없다.
- 계획 숨김·관리 해제·API 누락으로 기록을 삭제하지 않는다. OCID 변경도 이름으로 자동 연결하지 않는다.

## 10. 미검증 사항과 다음 소단계

남은 확인: 신규 난이도의 공식 가격과 정확한 적용 시각, 전체 보스 최대 파티 인원, 파티 이탈/특수 보상 자격, 게임 내 소수점 처리 공식 근거, 최신 월드 한도의 정확한 범위. 사용자 확정 공식은 유지하고 미검증 예외를 자동 적용하지 않는다.

| 소단계 | 범위 | 최소 검증·완료 기준 |
| --- | --- | --- |
| 7-B 제안 | 검증된 주간 자료, 정수 계산, 기간/clear group, v2 추가 마이그레이션, 수동 계획·클리어 저장/복원 | 인원/가격 오류·오버플로·목요일 경계·난이도 중복·revision 수정/해제/재완료·중복 요청·롤백; 본캐/키/선택 유지 |
| 7-C | 카드 진입, 주차별 UI·현재 관리 합계·과거 이력 | 합성 UI/타입 검사 후 필요한 Windows 개발 빌드 및 재실행 확인 |
| 7-D | 선택적 API 관측·사용자 수락 | flag/누락/월드 불일치/수동 충돌/반복 완료/429 합성 검증 후 필요 최소 실응답 |

각 소단계 완료 후 승인받는다. 가격 자료는 구현 직전 다시 변경 여부를 확인한다. 보조 자료를 공식 확인값으로 승격하지 않는다. 8단계 메소·아이템, 9단계 확장 통계, 10단계 배포는 별도 범위다.

## 11. 7-A 설계 작업 당시 검증 기록

설계·자료 조사만 수행했다. 코드·마이그레이션·DB·사용자 설정·Credential Manager는 변경하지 않았다. 개발 키 파일 존재/ignore/미추적을 확인했고 내용은 읽지 않았다. 실제 API 호출, 설치, 빌드, 패키징, 커밋·푸시는 0회다. 코드 변경이 없어 런타임 테스트는 실행하지 않았다. 문서 일관성을 확인했으며 실제 인게임 가격 대조는 미실시다.

위 검증은 7-A 설계 당시의 기록이다. 이후 승인된 7-B 구현은 [완료 보고](STAGE_7B_REPORT.md)에 별도로 기록했다. 이번 7-B 요청에는 기본 UI도 포함되었으며, 7-C는 시작하지 않고 다음 승인을 기다린다.

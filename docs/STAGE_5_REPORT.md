# 5단계 완료 기록 — 관리 캐릭터 선택 및 저장

작업일: 2026-10-28. AGENTS, 아키텍처, 개발 계획, 4단계 보고서와 기존 본캐·저장소·IPC·UI를 확인했다. 외부 maplemate 스킬은 사용하거나 참고하지 않았다. 이미지 조회와 메인 캐릭터 카드는 구현하지 않았다.

## 선택 기능과 검증

본캐는 자동으로 관리 순서 0에 포함하고 선택 해제할 수 없다. 추가 선택은 최대 5개, 전체 1~6개이며 OCID 중복을 금지한다. 신규 추가는 Rust가 마지막 성공 API 목록에서 본캐와 account_id·world_name이 모두 일치하는지 검증한다. 닉네임·직업 추정이나 React에 전달된 계정 값을 신뢰하지 않는다.

클라이언트는 선택한 OCID 배열, 현재 본캐 식별자, 선택 revision 및 목록 세대를 전달한다. Rust는 목록이 바뀌었거나 다른 작업에서 본캐/선택이 바뀐 오래된 저장을 거부한다. 본캐를 배열 앞에 정규화하고 추가 항목의 사용자 선택 순서를 보존한다. 검증 실패 및 DB 오류는 고정된 안전한 메시지로 안내하며 개인 정보·SQL·인증 헤더 원문은 노출하지 않는다.

기존 미조회 선택은 삭제하지 않고 마지막 메타데이터로 복원한다. 조회 결과가 없으면 아직 조회하지 않음, 누락되면 현재 조회되지 않음, 같은 OCID의 계정/월드가 바뀌면 식별 정보 불일치로 구분한다. 새 OCID나 닉네임으로 자동 재연결하지 않는다. 이러한 항목도 6개 상한에 포함한다.

API 목록이 없는 경우에도 기존 항목의 유지/해제는 저장할 수 있다. 다만 신규 추가는 허용하지 않는다. 본캐가 현재 목록에서 확인되지 않는 경우에도 기존 선택은 보존하고 새 추가만 막는다. API 실패·누락·응답 순서 변경만으로 DB 선택을 초기화하지 않는다.

## SQLite 스키마 및 마이그레이션

새 의존성은 없다. 기존 rusqlite와 사용자 앱 로컬 데이터 경로의 `ledger.sqlite3`를 재사용한다. API 키는 기존 Windows Credential Manager에 유지한다.

`002_managed_characters.sql`로 user_version 1→2를 적용했다.

- 기존 main_character를 유지한다.
- managed_character: position(0~5 기본키), OCID(고유), account_id, world_name, is_main, 표시용 이름·직업·레벨을 저장한다. 위치 0은 본캐, 1~5는 추가 캐릭터로 제약한다.
- selection_state: singleton=1, revision을 저장하여 다른 창/작업의 변경을 오래된 화면으로 덮어쓰지 않게 한다.
- 기존 본캐가 있으면 관리 위치 0으로 복사한다. 본캐 없는 새 DB는 선택도 비어 있고 본캐를 최초 지정하면 필수 선택을 만든다.

DDL·초기 본캐 포함·버전 갱신을 한 트랜잭션으로 처리한다. 마이그레이션 실패 시 새 테이블과 버전까지 롤백한다. 더 높은 DB 버전은 변경하지 않는다. 새로운 DB는 001과 002를 순서대로 적용한다.

선택 저장은 Immediate 트랜잭션에서 현재 본캐/revision 비교→개수·중복·소속 검증→관리 선택 행 교체→revision 증가를 수행한다. 본캐 변경도 같은 트랜잭션에서 main_character와 managed_character를 함께 갱신한다. 선택 테이블 외 기록을 삭제하는 SQL과 이력 연쇄 삭제는 없다.

## 본캐 변경 정책

같은 계정·월드:
- 새 본캐를 고정 관리 항목으로 지정한다.
- 기존 추가 선택에서 새 본캐와 중복되는 항목을 제외하고 나머지 순서를 유지한다.
- 기존 본캐는 자동으로 추가 선택하지 않는다.
- 현재 조회로 계정/월드 변경이 확인된 추가 항목은 제외한다. 단순 누락은 무효로 단정하지 않고 기존 선택을 보존하여 표시한다.
- 유지되는 추가는 최대 5개이며 결과 개수와 이전 본캐 처리 방식을 UI에 안내한다.

다른 계정 또는 월드:
- 기존 확인창에 추가 선택 초기화와 기록 보존을 명시한다.
- 확인 시 새 본캐만 선택한다. 취소 시 본캐·관리 선택 모두 유지한다.

동시 저장 충돌이나 선택 갱신 실패가 나면 본캐 변경도 롤백한다. 보스·메소·아이템 기록은 어떤 경우에도 이 작업에서 삭제하지 않는다.

## UI

동일 계정·월드 후보에 체크박스, 본캐 고정 표시, 선택 개수/6, 저장된 개수, 선택 순서 및 조회 상태를 표시한다. 선택 행은 배경색으로 구분한다. 6개에 도달하면 선택하지 않은 항목은 비활성화하고 안내하며, 선택된 추가 항목 해제는 계속 허용한다.

저장 버튼과 저장 전 변경 취소를 제공한다. 저장 완료 전까지는 화면 초안이며 성공/실패 안내를 구분한다. 본캐 변경 또는 목록 갱신 시 저장된 상태를 기준으로 다시 구성하므로 원하는 초안은 먼저 저장하도록 README에 안내했다. 미조회·식별 불일치 항목은 별도 상태로 남긴다. 중복 후보 표는 정리하고 관리 선택 목록에서 확인하도록 연결했다. 이미지·카드·별도 순서 편집 UI는 추가하지 않았다.

일반 테스트는 합성 데이터와 고유한 임시 SQLite 파일을 사용하며 사용자 DB를 오류/본캐 변경 승인 테스트에 사용하지 않았다. 임시 DB는 종료 시 정리했다. 실제 UI는 고정 선택·상한·해제·저장·재실행을 검증했으며 본캐 변경 승인/실패/미조회 상태의 모든 조합을 Windows 화면에서 재현한 것은 아니다. 해당 조합은 도메인·트랜잭션 테스트로 검증했다.

초기 컴파일에서 rusqlite의 기본 구성에 usize SQL 변환이 없어 오류가 발생했다. 저장 위치를 SQLite 정수에 맞게 i64로 명시한 후 관련 테스트를 실행해 통과했다. 같은 실패 명령을 원인 분석 없이 반복하지 않았다.

Windows 개발 빌드는 1회(약 12.25초) 수행했고 재실행에는 같은 바이너리를 재사용했다. API 명세의 목록 구간을 확인하고 사용자 등록 키로 목록 조회 1회만 수행했다. 기존 API 클라이언트·HTTP 필드·오류·키 저장 기능을 변경하지 않았으며 별도 실연동 테스트, 이미지 API 및 불필요한 반복 조회는 하지 않았다. 개발 TXT 키는 읽거나 수정하지 않았다. 개인 캐릭터 정보·식별자와 인증정보를 테스트 로그나 보고서에 남기지 않았다.

최종 표 중복 표시 정리 후 타입 검사를 다시 확인했다. 관리 선택 로직에는 추가 변경이 없어서 개발 앱 전체를 다시 빌드하지 않았다. 테스트 앱·서버·임시 UI 스크립트와 로그는 정리했다. 사용자 DB에는 마이그레이션과 본캐 고정 선택만 남기고 테스트 추가 항목은 해제했다. 배포 빌드·패키징·커밋·푸시는 하지 않았다.

## 남은 과제 및 6단계 계획

- 선택 순서는 본캐 우선·추가 선택 순서로 저장한다. 별도 순서 변경 UI는 아직 없다.
- 전체 API 목록의 재시작 캐시는 아직 없어 신규 선택에는 수동 조회가 필요하다. 기존 선택·순서는 조회 없이 복원되고 명시적인 추가 항목 해제는 가능하다.
- 다중 API 키 프로필과 실제 장부는 아직 구현하지 않았다. 조회되지 않는 선택을 사용자가 해제하거나 본캐 범위를 바꾸기 전까지 자동 삭제하지 않는다.
- 다음 6단계는 저장된 최대 6개를 순서대로 메인 카드에 표시하고, 선택 대상에만 기본 정보/이미지를 최소 조회하여 캐시하는 기능이다. 조회 실패·이미지 없음·오프라인에는 보존 정보와 자리 표시자를 사용한다. 실제 구현과 상세 캐시 정책은 사용자 승인 이후 진행한다.

5단계 완료 후 멈추고 사용자 승인을 기다린다.

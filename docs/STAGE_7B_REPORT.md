# 7-B 완료 기록 — 주간 보스 관리 기본 기능

작업일: 2026-10-28. 사용자 요청에 따라 7-A의 분할안에 있었던 카드 진입·기본 UI까지 이번 7-B 범위에 포함했다. AGENTS, 보스 설계·가격 조사, 아키텍처·개발 계획과 현재 코드를 확인했다. 외부 maplemate 스킬은 사용하거나 참고하지 않았다.

## 1. 구현 기능

- 기존 캐릭터 카드의 보스 관리 버튼 및 대시보드 주간 보스 진입. 기존 카드·본캐·최대 6개 관리 선택·키 설정은 유지했다.
- 공통 24개 주간 보스/54개 난이도에서 캐릭터별 추적 여부·난이도를 독립 저장한다. 관리하지 않는 보스는 기본 기록 목록에서 숨긴다. 기존 기록이 있는 보스는 관리 해제 표시와 함께 남긴다.
- 필수 파티 인원(기본 1), 클리어 체크, 날짜, 저장, 해제, 난이도/가격/인원 수정과 revision 이력을 제공한다. 계획 난이도 변경은 과거 클리어를 자동 변경하지 않는다.
- 클리어 기록 시 개인 정수 수익을 저장하고 캐릭터/현재 관리 전체 합계에 반영한다. 해제·수정은 최신 revision만 반영한다. 미산정은 별도 건수이며 0메소 수익으로 취급하지 않는다.
- 현재/이전/다음 주차 이동, 과거 기록 수정, 관리 해제 캐릭터 이력 조회를 제공한다. 새 보스 설정은 현재 관리 캐릭터만 가능하며 관리 해제 캐릭터는 기존 기록만 수정할 수 있다.
- 적용 가격·출처·자료 버전·계산 버전·당시 캐릭터 식별을 스냅샷으로 저장한다. 수동 가격과 확인 근거 입력도 지원한다.
- 판매 여부·판매일·판매 원장, 메소 잔액, 아이템, 스케줄러 연동 및 가격 자동 갱신은 구현하지 않았다.

## 2. SQLite v2 → v3

추가 파일은 `src-tauri/migrations/003_bosses.sql`이다. 기존 001/002는 수정하지 않았다. 기존 저장소의 버전 분기에 v3를 추가하고 연결별 foreign_keys를 활성화한다. 이전과 동일한 사용자 앱 데이터 경로를 사용한다.

| 테이블 | 저장 내용 |
| --- | --- |
| record_characters | OCID 영구 식별, 계정/월드, 표시 정보 JSON. 관리 선택 행과 독립 |
| character_boss_plans | 캐릭터+보스별 선택 난이도·활성 상태·설정 revision |
| boss_periods | 시작/종료 일자 키, Asia/Seoul, 초기화 규칙 버전 |
| boss_clear_records | 캐릭터+주차+제한 그룹의 유일한 기록, current_revision |
| boss_clear_revisions | 요청 ID/요청 JSON 및 당시 계산·가격·정정 스냅샷 JSON |

기존 관리 캐릭터를 영구 식별에 등록하고 main_character/managed_character/selection_state를 보존한다. API 키는 계속 Credential Manager에만 있다. 보스 이력은 선택 행/position을 참조하지 않으며 관리 선택 교체로 삭제되지 않는다.

마이그레이션은 하나의 트랜잭션이며 SQL 실패 시 user_version와 기존 데이터가 유지된다. 임시 v2 DB의 테이블 충돌로 롤백을 검증했다. 알 수 없는 상위 버전은 기존처럼 거부한다. 별도 자동 백업 시스템은 추가하지 않았다.

기록 저장은 Immediate 트랜잭션에서 현재 선택 revision 및 기록 revision을 검사한다. 새 스냅샷과 현재 포인터를 함께 저장하고 지연 FK로 포인터 무결성을 보장한다. 동일 요청 ID 재전송은 기존 결과를 반환하며 다른 내용으로 재사용하면 거부한다. 수정 충돌은 새로고침 안내로 처리한다.

## 3. 가격 자료와 계산

`src-tauri/resources/bosses.json`을 컴파일에 포함한다. 자료 버전은 `kms-2026-10-28-v1`, 계산은 `party_floor_v1`이다. 의존성이나 패키지를 추가하지 않았다.

- 공식 확인 금액 51개: 9월 조정 44개, 유지되는 6월 가격 5개, 10월 22일 최신 변경 2개.
- 벨로나 하드·림보 익스트림·발드릭스 익스트림은 공식 가격 미확인으로 null이다. 보조 자료 숫자를 자동 가격으로 넣지 않았다.
- 월간 검은 마법사, 일간으로 변경된 보스와 결정석 미지급 시즌 보스는 주간 카탈로그에서 제외했다.
- 가격 근거/적용 시작일과 알려진 난이도 제한 그룹을 자료에 포함했다. 림보/발드릭스 노멀·하드의 공식 확인된 3인 상한만 적용하며 미검증 상한은 임의 강제하지 않는다. 전역 주간 처치 한도를 앱이 전체 게임 상태로 오인해 강제하지 않는다.

계산은 Rust i64의 양의 정수 가격/인원 나눗셈이다. 예: 4,040,000/3=1,346,666메소. 합계는 나눗셈 후 개별 결과를 checked_add로 합산한다. 프런트 미리보기는 BigInt, 금액 DTO는 십진 문자열이다. 부적절한 가격/인원, 정수/합계 오버플로를 거부한다.

점검일의 정확한 가격 전환 시각은 미검증이다. 클리어 날짜가 해당 적용일 당일이거나 주차만으로 시점이 불명확하면 자동 계산하지 않는다. 날짜를 확인하거나 1인 기준 수동 가격과 근거를 입력한다. 최신 가격 이전 구간에 오늘 가격을 소급 적용하지 않는다.

기록 수정 시 같은 난이도/날짜이고 새 가격 입력이 없으면 당시 가격·버전을 유지한다. 인원 변경은 그 가격으로 다시 계산한다. 날짜/난이도를 명시적으로 바꾸면 새 적용 가격을 판정한다. 수동 가격은 해당 기록에만 적용한다. 더 오래된 가격 이력을 전부 내장하지 않았으므로 일부 과거 기록은 미산정/수동 확인이 필요하다.

## 4. 주차 및 합계

KST(UTC+09:00) 목요일 00:00을 경계로 시작 포함·종료 제외 7일 구간을 사용한다. Unix 일자 키와 Gregorian 변환으로 구현해 시간 라이브러리를 추가하지 않았다. ISO 월요일 주차나 PC 현지 시간대를 사용하지 않는다.

앱 시작/화면 진입 시 현재 시간을 기준으로 조회한다. 실행 중 30초 간격 및 창 포커스/보스 화면 복귀 이벤트로 경계를 확인한다. 앱이 꺼져 있어도 재실행하면 올바른 주차를 조회한다. 과거 행 삭제나 완료값 일괄 초기화를 하지 않는다. 백그라운드 Windows 서비스는 없다.

합계는 각 clear record의 최신 완료 revision만 사용한다. 주차는 수정일이 아닌 기록의 귀속 주차다. 추적 해제도 기존 주차 수익을 삭제하지 않는다. 현재 관리 전체는 관리 OCID 집합으로 필터링하며 관리 해제 캐릭터의 이력은 별도로 조회된다.

## 6. 실제 Windows 개발 UI

별도 임시 DB(합성 관리 캐릭터 2개)로 실제 Tauri/WebView2 앱을 실행했다. DB 파일을 직접 조작해 결과를 가장하지 않고 화면의 입력/버튼과 실제 IPC를 통해 기록했다. 화면 캡처도 확인했다.

| 실제 확인 항목 | 결과 |
| --- | --- |
| v2 시작 및 기존 카드/본캐/선택 | 합성 v2 DB가 v3로 이전되고 2개 카드·기존 본캐 복원 |
| 카드 → 보스 관리 | 24개 보스 그룹/54개 난이도 표시 |
| 선택·파티·클리어 저장 | 자쿰 3인 → 1,346,666메소, 캐릭터/전체 합계 반영 |
| 취소·재완료 | revision 1→2→3, 취소 시 0, 재완료 후 한 번만 합산 |
| 이전/현재 주차 | 이전은 별도 상태, 현재 복귀 시 기존 기록 유지 |
| 추적 해제 | 클리어 기록과 수익 유지 |
| 미확인 가격 | 익스트림 림보 완료 시 미산정 1건, 0메소 수익으로 표시하지 않음 |
| 수동 가격 확인 | 합성 확인 가격/근거를 입력해 3인 개인액 반영, 새 revision 보존 |
| 다른 캐릭터 | 계획·개별 수익이 독립, 전체 합계는 유지 |
| 기존 키 설정 | 등록 상태와 비어 있는 키 입력 확인. 키 원문을 IPC/화면으로 받거나 변경하지 않음 |
| 실제 프로세스 종료/재실행 | 계획·인원·당시 가격·합계·5개 revision 및 기존 본캐/관리 설정 복원 |

최초 앱 실행에서 새 Command의 manifest/메인 창 권한 등록 누락으로 호출이 차단되었다. build.rs와 capability의 좁은 허용 목록을 추가하고 개발 빌드를 다시 수행한 뒤 위 흐름이 통과했다. 개발 앱 빌드는 총 2회(약 19.92초, 12.38초), 이후 재실행은 같은 실행 파일을 사용했다. 테스트 컴파일과 구분한 수치다. 작은 UI 문구 수정은 타입/SSR 검사와 Vite 갱신으로 확인했다.

개발 전용 `MAPLE_LEDGER_CHECK_DIR`는 OS 임시 디렉터리 하위의 분리 DB로만 연결하고 release에서 제외된다. `MAPLE_LEDGER_OFFLINE_CHECK`는 debug 카드 갱신을 인증 저장소 접근 전에 차단한다. 따라서 기존 카드의 자동 정보 조회가 있는 앱에서도 이번 검증의 넥슨 HTTP 호출은 **0회**다. 임의 경로/SQL을 실행하는 IPC는 추가하지 않았다. 개발 TXT 키는 읽지 않았다.

실제 사용자 DB의 전후 SHA-256이 동일했고 사용자 키도 유지되었다. 사용자 DB는 이번 UI 검증에서 이전하지 않았다. 정상 앱 실행 시 사용자 DB의 v2→v3 이전은 검증된 저장소 마이그레이션을 따른다. 주간 경계는 합성 시간 테스트로 검증했으며 실제 Windows 시간을 변경하거나 다음 목요일까지 대기하지 않았다. 실제 캐릭터/실제 가격 획득 결과와 대조한 검증은 아니다.

## 8. 남은 문제와 후속 제안

- 공식 미확인 3개 가격, 가격 적용일 당일의 정확한 경계, 보스별 미확인 인원/특수 보상 예외는 자동 추정하지 않는다.
- 게임 전체 처치·월드 판매 한도는 앱 기록만으로 알 수 없다. 전량 판매 가정 수익이며 실제 잔액은 아니다.
- 가격/카탈로그 자동 업데이트, 스케줄러 관측·사용자 수락, 메소 잔액·아이템, 배포는 미구현이다.
- UI 초안은 기록 저장 버튼으로 반영된다. 주차/캐릭터 이동 전에 저장해야 한다. 다른 저장과 충돌하면 기존 DB를 덮어쓰지 않고 새로고침을 안내한다.
- 추가 UI 정리/선택적 API 관측 중 다음 범위를 사용자와 정한다. 이번 요청의 UI는 7-B에 포함하여 완료했으며 이전 7-C 계획을 자동 실행하지 않는다.

검증용 앱·Vite 서버와 임시 스크립트/DB/캡처는 종료·정리했다. production/release 빌드·설치 패키지·커밋·푸시는 수행하지 않았다.

**7-B 완료 후 멈추고 사용자 승인을 기다린다. 7-C는 시작하지 않는다.**

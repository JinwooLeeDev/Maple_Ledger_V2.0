# 7-E 스케줄러 등록 보스 목록 표시

작업일: 2026-10-28 KST. 목표는 캐릭터별 주간 등록 보스 표시, 예상/실제 수익 분리, 실패 시 목록 및 기존 기록 보존이다. 7-C·7-D 클라이언트와 저장 구조를 재사용했다. 외부 maplemate, 의존성 추가, 커밋·푸시, 배포 패키징은 하지 않았다.

## 구현

- `bossWeekly`이며 `registration_flag=true`인 항목만 기본 목록으로 표시한다. 표시 행 개수와 등록 개수는 같은 배열을 사용한다.
- API 원문 보스 이름과 난이도를 행 제목에 표시한다. 기존 정확 매핑을 재사용하며 확인된 난이도 대응과 듄켈 이름 대응 외의 추측·대체는 하지 않는다. 미매핑 항목도 그대로 표시하고 가격 미확인·입력 불가로 처리한다.
- 행별 결정석 가격, 기록된 클리어, 기록 파티 인원, 저장된 개인 수익과 조회일 기준 API 완료 여부를 구분한다. 기존 기록 편집기를 재사용하고 등록 난이도로 입력을 제한한다. 다른 공유 난이도 기록이 있으면 같은 revision 계열을 정정하며 자동 덮어쓰지 않는다.
- 상단 실제 주간 합계는 기존 현재 유효 revision 합계를 유지한다. 등록 목록에는 결정석 가격 합계와 예상 개인 주간 수익을 따로 표시한다. 예상은 각 가격/기록 인원의 정수 몫 합계이며 인원 미기록은 솔로 추정이라고 명시한다. 가격 또는 적용 시점이 미확인이면 미산정 건수로 표시하고 합계에서 제외한다.
- 수동 보스 선택 UI·설정은 유지한다. 스케줄러에 없는 기존 기록은 기존 별도 기록 영역에서 확인·정정한다. 과거 주차도 기존 탐색과 수정 이력을 유지한다.

## 실패·빈 응답 및 데이터 보존

기존 `boss_api_observations` 이력을 최신순으로 읽어 등록 주간 항목이 하나 이상인 마지막 정상 목록을 복원한다. 별도 migration이나 기존 행 수정은 없다. 최신 완료 관측과 목록 캐시는 별도 DTO로 반환한다. 빈 응답·전체 미등록 응답은 마지막 정상 목록을 지우지 않는다. 정상 목록이 없으면 수동 관리 목록을 표시한다. 데이터 출처와 목록 조회일을 명시한다.

목록은 캐릭터 OCID별로 분리하며 조회 주차보다 미래 관측은 사용하지 않는다. 이전 주차 목록은 조회일을 표시한 채 재사용하지만 이전 완료 여부를 현재 기록으로 반영하지 않는다. 등록 갱신은 클리어·revision·수동 선택·저장 금액을 변경하지 않는다. 등록된 매핑 보스는 수동 선택을 자동 저장하지 않고 Rust에서 등록 여부를 확인해 새 수동 기록을 허용한다. API 완료 수락은 기존 명시적 사용자 확인 경로를 유지한다.

최종 편집기 초기값 수정 후 타입·합성 화면 검증을 다시 통과했다. 추가 native 재검사는 이미 보스 화면인 상태에서 진입 버튼을 찾는 검증 스크립트 전제 때문에 실패했다. 스크립트를 현재 화면에서도 실행 가능하도록 수정했으며 이 수정 이후 native 재검사는 하지 않았다. 앞선 최초 실행 및 실제 프로세스 재실행 검증은 통과했다. 검증 앱은 종료했다.

개발 키 존재·ignore·미추적 및 해당 경로 Git 이력 없음 확인. 키 내용은 읽거나 출력하지 않았다. 실제 API 호출 0회. 사용자 DB와 Credential Manager는 검증에 사용하지 않았다. Node 검증은 샌드박스의 사용자 경로 접근 제한으로 승인 후 실행했다.

## 남은 문제·미검증

- 실제 계정의 최신 난이도 및 초기화 경계에서의 API 등록 갱신 시점은 이번에 재검증하지 않았다. 7-D의 단일 캐릭터 실호출 근거와 기존 정확 매핑을 재사용했다.
- 빈 등록 목록은 사용자 요청대로 삭제 지시로 해석하지 않는다. 실제로 모든 보스를 해제한 경우에도 정상 캐시가 있으면 유지되며 조회일을 함께 표시한다.
- 캐시는 과거 관측 JSON을 읽는다. 장기간 관측 증가에 대한 성능 측정은 하지 않았다.
- 배포 빌드·패키징과 다른 Windows PC 검증은 하지 않았다.
